# Production frontend measurements

Measure loopback static assets with the checked-in `_headers`, gzip transfer,
and a fresh offline API store. This does not connect to a hosting provider.

Install the measurement tools separately from the application lock:

```bash
npm install --prefix /tmp/fp-tools lighthouse@12.8.2 playwright@1.61.0
```

After root `make setup`, start the API from `app/` in a separate terminal:

```bash
mkdir -p /tmp/fp-state
COSCIENTIST_TEST_DOUBLE=deterministic PYTHON_DOTENV_DISABLED=1 \
EVIDENCE_RESOLVER=offline COSCIENTIST_DB_PATH=/tmp/fp-state/coscientist.db \
MCP_SERVER_URL=http://127.0.0.1:9/mcp ALLOWED_ORIGINS=http://127.0.0.1:5273 \
../.venv/bin/python -m uvicorn co_scientist.main:app --host 127.0.0.1 --port 8108
```

From `app/frontend/`, build and seed, then leave the preview running:

```bash
bun run build
node scripts/performance/seed.mjs
openssl req -x509 -newkey rsa:2048 -nodes -days 1 \
  -keyout /tmp/fp-local.key -out /tmp/fp-local.crt \
  -subj /CN=127.0.0.1 -addext subjectAltName=IP:127.0.0.1
FP_TLS_CERT=/tmp/fp-local.crt FP_TLS_KEY=/tmp/fp-local.key \
node scripts/performance/serve.mjs dist
```

Run in another terminal from `app/frontend/`:

```bash
FP_CHROME=/usr/bin/chromium FP_TLS_CERT=/tmp/fp-local.crt \
FP_ORIGIN=https://127.0.0.1:5273 \
node scripts/performance/measure.mjs /tmp/fp-before
```

`FP_TOOLS`, `FP_ROUTES`, `FP_API`, `FP_ORIGIN`, and `FP_PORT` override the
tool directory, seeded route file, loopback API, preview origin, and port.
Use a unique state directory for each independent measurement run.
Never use a developer or production store. Stop this API before running the
full Python or browser suites; the browser gate owns port 8108.

TLS serves HTTP/2, matching Cloudflare's multiplexed visitor connection.
The runner trusts only the supplied local certificate's public key; it does
not disable certificate checks for other origins. Gzip is used conservatively
on both before/after assets rather than assuming a zone's Brotli/Zstandard
compression settings. To retain the HTTP/1.1 control cohort, omit both TLS
variables from the server and use the HTTP origin without `FP_TLS_CERT` in the
runner. Keep transport identical between before and after and label it in
the table. This preview models headers/transport, not edge latency or a
hosting configuration inspection.

The runner measures fresh-cache navigation with Lighthouse's default mobile
slow-4G simulation (150 ms RTT, 1,638.4 kbit/s, 4× CPU slowdown) and desktop
preset. It preserves only local theme/owner state and clears the browser's
HTTP cache before every audit. TBT is the lab proxy recorded here; navigation
Lighthouse cannot supply field INP. Raw reports retain exact throttling,
browser version, resource transfers, warnings, LCP element, and shift causes.
Avoid running builds or test suites concurrently with timing measurements.

Home and landing share `/`: the first viewport is the composer. The landing
is below the desktop fold and absent at phone widths. Its navigation metrics
therefore equal home's; a separate scrolled screenshot verifies the desktop
landing. Example measures the curated report directly, rather than the
`/examples/:id` action that creates a private example chat. Run measures a
completed Express report generated by the real offline backend. Both use the
Research Overview tab and must render its heading before screenshots.

Screenshots cover 390 and 1440 pixels in both themes, with reduced motion,
loaded fonts, settled requests and disabled animations. The third-party video
frame is masked; its remote content changes independently of this build.
Compare corresponding before/after PNGs; inspect any difference
before accepting a performance change. Raw reports and screenshots are scratch
artifacts, kept outside the repository.

Targets: mobile LCP ≤2.5 s, CLS ≤0.1, initial landing JavaScript ≤200 kB gzip.
Results reflect local static serving and deterministic data; they exclude
edge latency and production report-size variation.

Also measure a telemetry-enabled build using
`VITE_SENTRY_DSN=https://public@127.0.0.1:5273/fp-sentry/1`. The preview discards
that local receiver's payloads without forwarding or storing them. No real
monitoring DSN is needed.
